# 卡片 / 事件与进销存新模型对齐（2026-09 卡片层优化）

> 背景：进销存数值设计先后改动——基础销售资源 10→4、加点成本高端 4 / 特殊 6、
> 订单槽 4 人 2 单、初始资金 30w→50w、产能新模型（老板 5 + 工人 ×（5~7）+ 加班 10）、
> 设备改为「每名生产人员 +2」、采购人员不再提供供给加成、现货 100% 确定成交。
> 但卡牌与事件的正文 / 数值没有随之校准，出现三类问题：
> ① 数值与新基线不匹配（产能卡 +1/+2 偏弱、文案「产能 10 设备」是旧槽位模型遗留）；
> ② 文案与代码实际效果不符（承诺的条件分支没人消费、强化版文案与代码不一致）；
> ③ 口径重复计算（采购卡档位修正在「展示档位」与「采购价」里各算一次）。
>
> 本文记录梳理结论与本次改动；所有公式仍以 `src/core` + `src/data/game.ts` 为准。

## 1. 进销存现状基线（改动前，代码口径）

| 系统 | 当前数值 |
|---|---|
| 基础需求 | 低 5 / 中 4 / 高 2 / 特 1（件/月）；气候修正只拆低/中（60/40） |
| 销售资源 | 池 = 基础 0 + 销售阶梯（累计 4/8/14/20/28）+ 知产 + 品牌 + 事件/卡牌；加点成本 低 1 / 中 2 / 高 4 / 特 6，上限 15/12/6/3 |
| 订单 | 销售 2 人 1 单 / 4 人 2 单；每单 8~12 件；订单价 = 市价 +1 档（知产/事件可再升） |
| 产能 | 5（老板）+ 生产人数 ×（5，≥2 人 +1，≥4 人 +1，每台设备 +2）+ 加班 10（生产 ≥3 人） |
| 采购 | 档数 = 2 + 采购人数（2~7）；小批 +1 档 / 大批 −1 档；贸易商小批 +1 档（采购 4 人回到基准） |
| 现金 | 开局 50w |

## 2. 主要不一致（已修复）

### 2.1 文案与代码不符（死条件 / 错位文案）

| 条目 | 问题 | 处理 |
|---|---|---|
| C1 批量采购 | 「采购档数 ≥ 2 额外降 1 档」的 `buyTierExtra` 无人消费 | 在 `buyCardShift` 落地：自第 2 个已选档起 −1 档；基础版也携带该 flag |
| C3 压价 | 强化文案「降 3 档」，但 C3 无 `strong`，强化实例走 base（只降 2 档） | 补 `strong: { buyTierShift: -3 }` |
| C4 贸易商 | 「价格不变 / 可指定品种」与代码不符（价格恒 +1 档，品种由人数决定） | 文案改为「+1/+2 次购买机会（小批、价格 +1 档、不占档数）」 |
| C6 紧急采购 | flag 置位后无消费端（零效果卡） | 采购页新增「紧急采购」入口：每原料 1 次，小批 +2 档（强化中批 +1 档），不占档数 |
| C7 原料替换 | 同上 | 采购页新增「原料替换」：按账面单价出 5 单位、按当前价购 5/7 单位，每月 1 次、不进损益 |

| C10 清仓 | 同 C6 | 采购页新增「清仓采购」：每原料 1 次，小批 −2 档（强化中批 −2 档），不占档数 |
| P1 满负荷 | 「产能全用完额外 +1」无人消费；+2 对 10~40 产能基线偏弱 | 改为无条件的 +3（强化 +6），删 `fullLoadCard` 特例 |
| P3 加班卡 | 「可支付 2w 改 +5」无人消费；+3 且每人薪酬 +1w 偏贵且与内置加班（+10/0.5w）语义混淆 | 改为 +4、每人薪酬 +0.5w（强化 +7、+1w），删 `overtimeCard` 特例 |
| P4 设备维护 | +1 太弱 | +2（强化 +4） |
| P10 库存清理 | flag 置位后无人消费（零效果卡） | 结算 §3 段落地：按账面单价出售成品库存最多产品的 5/10（强化 10/15）件，资产转现金、不进损益 |
| R6 逆向工程 | 文案「已研发产品的 BOM」，实际解锁的是**未解锁**配方 | 文案改为「按中端 → 高端 → 特殊顺序解锁 1/2 个未解锁配方」 |
| R10 知识产权保护 | 「知识产权不会被事件影响」无人消费 | 文案聚焦真实效果：研发 ≥5 人（强化无门槛）激活槽 +1 |
| S10 高端市场 | 强化文案「高端、特殊 +2 档」与代码不符（强化高端仍是 1 或 2） | 代码改为 强化 = 高端 +2、特殊 +2 |
| M1 抽 1 弃 1 | 文案「弃 1 张，弃业务卡再抽」，实际只抽 1 张 | 更名「抽牌」：抽 1 张入手（强化抽 2 张） |

### 2.2 数值与新基线不匹配（产能卡整体重标）

产能基线 10（1 工人）~ 40（5 工人），原 +1/+2 卡牌中后期近乎无感。统一上调（强化档同步）：

| 卡 | 原（基础 / 强化） | 新（基础 / 强化） |
|---|---|---|
| P1 满负荷 | +2（+1 条件） / +4（+2 条件） | +3 / +6 |
| P2 质量管控 | +2 / +4·成本 −10% | 保持 +2 / +4·−10%（定位偏低、含降本） |
| P3 加班 | +3·薪酬 +1w / +5·+1w | +4·+0.5w / +7·+1w |
| P4 设备维护 | +1 / +3 | +2 / +4 |
| P5 工人培训 | 按人数（3 人 +3 ~ 5 人 +15） | 保持（随人数缩放，已是强卡） |
| P6 批量生产 | +2（≥5 人 +3） / +4（+5） | +2（≥5 人 +4） / +4（≥5 人 +6） |
| P7 精益生产 | +1·−10% / +2·−20% | +2·−10% / +3·−20% |
| P8 轮班制 | +2·+0.5w（≥3 人免罚） / +4 | +2·+0.5w（≥3 人免罚） / +4（免罚） |
| P9 自动化 | +2（rnd≥3 +4） / +4（+6） | 保持 |

事件侧同步：P2（事件）产能满载 +2 → +3。

### 2.3 文案口径统一（与结算/展示一致）

- 薪酬类一律写「**每名**员工薪酬 ±x（全部门）」：P3/P8/S6 卡、P4/O2/S10/D5 事件（`salaryPer` 是全局每人修正，不是部门总额）。
- 销售资源类补换算说明（资源 → 需求点）：S2「+5（可推低端 +5 / 中端 +2 / 高端 +1）」、S6「+3（低端 +3 / 中端 +1）」、事件 R8「+4（低端 +4 / 中端 +2 / 高端 +1）」。
- 订单类写清数量与价格基准：S3/S8「10 件、订单价高于市价 1 档、月末结算交付」；事件 P9 文案「订单价高于市价 2 档」（代码 = 基础 +1 档 + 事件 +1 档）。
- 设备类按新模型改写（设备 `capacity` 字段已弃用，实际效果 = 每名生产人员 +2）：事件 P6/D9/X9 改为「产线（每名生产人员产能 +2、月折旧 0.2w/0.1w；无生产人员则产能无增益）」。
- 长期协议写死默认标的：O6/D7 文案「锁定一种原料」→「包材长期协议」（代码确实签 `MATERIALS[0]`，UI 无原料选择）。
- X5 破产潮：实际效果是「招聘费 −50%」（`hireCost` 读 notes），原文案「收购 1 名员工」不符，已改。
- S5 库存积压：实际是「下月全部产品市价 −1 档」，原文案「本月生产入库的产品」不符，已改。
- X8 技术储备：临时知产明确写「本季有效」（代码进 `tempIps`，非永久）。
- R2/S8（事件）研发降本：明确「每个在研项目」口径（`rndCost` 按项目计）。

### 2.4 口径修正（重复计算 / 双签）

- **采购卡档位重复降档**：`cardEffectToMods` 原来把 `buyTierShift` 并进 `cardMods.allTierShift`（展示档位），`lotPrice` 又叠加 `buyCardShift`（同一张卡再算一次）→ C1 实际 −2 档。现改为：卡牌档位修正只在采购时（`buyCardShift`）生效，展示档位 = 气候 + 事件 + 人员 + 知产。价格拆解页的「卡牌修正」行与最终价从此一致。
- **O6/D7 双签协议**：`applyEventOption` 同时命中「长期协议」与「签订 1 份」两个分支 → 一次签 2 份。删「签订 1 份」分支（月数由 detail 的「6 个月」判定），各签 1 份。
