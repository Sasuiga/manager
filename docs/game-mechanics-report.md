## 1. 项目概览与两种模式

游戏是一局 12 个月（4 个季度）的单机生产经营刷分游戏。玩家扮演总经理，通过**采购原料 → 排产生产 → 销售（订单 + 现货）**维持现金为正、让董事会满意，最终按净利润 / 净资产 / 目标 / 成就计分。

代码中存在两种运行模式（`GameMode`，`src/core/types.ts`）：

| | 完整模式 `full` | 核心模式 `core` |
|---|---|---|
| 入口 | 标题页「开始新的一局」 | 「自由核心实验」+ 6 个固定场景 |
| 阶段 | 董事会 → 事件 → 抽卡 → 经营 → 结算 → 报表 | 事件 → 抽卡（立项）→ 经营 → 预算预演 → 结算 → 报表（无董事会） |
| 部门页 | 运营/采购/生产/销售/研发 5 页 | 运营/采购/生产/销售/研发 5 页（同完整模式，含管理部门与提案实施） |
| 采购 | 选档立即扣款入库 | 只形成**采购计划**，结算时统一付款入库 |
| 生产 | 「确认生产安排」立即扣料入库（结算时不再重复） | 无确认按钮，排产在结算时一次过账 |
| 现货成交 | 需求 100% 确定成交 | 同完整模式：公开需求 100% |
| 卡牌 | 每月「抽 N 选 M」 | 同完整模式：每月「抽 N 选 M」（两模式均经 `enterDraw` 立项阶段） |
| 知产生效 | 激活槽制（1/2/3 槽，每月最多换 1 次） | `ipOwned` 拥有即生效（`src/core/derive.ts:199`） |
| 设备购买 | 完整模式专属（事件也可送设备） | 无设备（每人产能的设备 +2 项占位，数量恒 0） |
| 董事会目标 | 有（季度初抽，连续 2 季未达基本目标出局） | 不生成目标，`misses` 恒 0，不会因目标出局 |
| 开局解锁 | 仅低端产线（`src/core/game.ts:85-88`） | 同 |

**两种模式共享**：原料库存/移动加权平均计价、产能模型、人员招聘、研发放置模型、订单/现货结算、工资计提、复式记账、资产负债表、确定性 RNG。

模式差异的散布点：`state.mode` 分支出现在 `actions.ts`（`buyMaterial` 538 行分流到 `setPurchasePlan` 555 行、`committableProductQty` 1147 行加排产、`confirmProduction` 1086 行拒绝）、`settle.ts`（spotFactor 240 行注入倍率，原核心模式随机因子已移除）、`derive.ts`（`activeIps` 199 行知产生效口径）、`engine.ts`（`startGame` 116 行 / `nextMonth` 303 行阶段分流）。

> 注：本文行号以 2026-09-27 工作区为准，合并分支后可能漂移，函数名是稳定锚点。

## 2. 单位系统与数字约定

- **货币单位 = 「角」**（`Money` 类型，1w = 10）。全部内部运算是整数「角」，展示层统一经 `wan()`（`src/ui/format.ts:12`）换算为 `x.xxw`（两位小数）。数据文件 `src/data/game.ts` 中所有货币常量都是角：如 `START_CASH = 1000`（10w）、`OVERTIME_COST = 5`（0.5w）、`RND_COST_PER_PROJECT = 30`（3w）。
- **RNG**：mulberry32（`src/core/rng.ts`），状态可序列化。同一 seed 一局完全可复现。多处用 `Rng.fromState(seed + month * 常数)` 派生独立子流，保证某类随机（订单量、现货系数、事件池、目标）与主随机流互不干扰。
- **预览与结算同源**：界面上所有「预计值」由 `derive()`（`src/core/derive.ts:268`）与结算共用同一套公式，预算页（`preview.ts`）通过**克隆状态跑两遍真实 `settle()`** 得到区间，保证预演数字与实际结算口径一致（`src/core/preview.ts:132`）。
- **库存计价**：原料与成品一律**移动加权平均**。账面只存 `qty` 与 `value` 两个字段，单价 = `value / qty` 现算（`src/core/types.ts:55-60`），避免取整漂移。生产领料、销售成本结转、成品入库全部与账面 `value` 严格勾稽（会计恒等式审计见 `src/core/audit.test.ts`，全年最大偏差要求为 0）。
- **舍入**：金额几乎不取整（浮点角值一路保留到报表展示时 `toFixed(2)`）；个别地方 `Math.round`：成品 `avgCost` 展示、单件标准成本 `unitCost`、`cogs` 的 SaleRecord 记录（`cost` 字段是精确值，`unitCost` 字段是取整展示值）。

## 3. 月度流程（阶段状态机）

`Phase`（`src/core/types.ts:39`）：`title → board → event → draw → operate → settle → report → gameover/summary`。

### 完整模式（每月）

```
季度首月(1/4/7/10)：
  ① 董事会（BoardScreen）：展示基本目标（必达）+ 从 2 个挑战目标里选 1 个（可不选）。
     目标由 drawBoardGoals() 抽取（engine.ts:129），季度首月才抽，其余月份沿用。
每月（事件阶段，engine.ts:206 beginMonthEvent）：
  ② 事件：从事件池抽 1 张（见 §11）。
     - 即时事件：抽到即生效（mods 并入 monthMods，eventResolved=true）；
       注意 App.tsx 会把"已解决的即时事件"当作未进入经营，再次调用 beginMonthEvent，
       即连续抽事件直到抽到「抉择/机会」事件才停（该月可能叠加多张即时事件，只展示最后一张，见 §18）。
     - 抉择事件：二选一（可花现金/AP）。
     - 机会事件：参与（付现金或 AP）或放弃。
每月（立项阶段，engine.ts:236 enterDraw）：
  ③ 抽卡：自动抽 N 张到「待选区」，玩家选 M 张入手，未选中放回牌库；
     手牌超上限时进入「废案模式」必须弃够张数才能进经营。
     每月渠道订单也在这一阶段生成（generateMonthlyOrders，engine.ts:272）。
经营阶段（operate）：
  ④ 五个部门页自由进出操作（见 §4）：招聘、打牌、采购、排产、接单、分配销售资源、
     研发放置、设备、协议、借款等。
结算（App.tsx SettleFlow）：
  ⑤ 「结算」按钮 → 确认弹窗（风险提示）→ settleMonth() → 结算报表（ReportSheet）
     → 「进入 N+1 月」→ advanceMonth（settle.ts:813）。
```

`advanceMonth`（settle.ts:813-895）做的事：月份 +1；按人数重算 AP/打牌数/手牌上限/抽牌参数；
结转 `nextMonthPrice` 到下月（库存积压类修正）；清空 monthMods/cardMods/monthFlags/计划/分配/
档数/订单接受列表；挂账收付（`pendingIncome` 到账 / `pendingCost` 偿还，只动现金不动损益）；
长期协议 `monthsLeft - 1`；**季度切换时掷气候与动能**（见 §5.1）；按管理人数把新解锁管理卡补入牌库。

### 核心模式（每月）

```
startGame / nextMonth（engine.ts:116/303）：
  phase='event'（每月 1 张事件，池按 needs 过滤：融资类全模式剔除、卡牌参数类两模式保留——核心也有立项抽卡阶段）
  → 确认后 enterDraw 进入立项（抽卡）阶段（抽 N 选 M，与完整模式一致）→ 经营阶段。
  generateMonthlyOrders（订单数 = 销售人数 + 知产 + 卡牌驱动，见 §8）。
  无董事会、无设备购买、无知产槽位；AP = 3 + 管理人数−1（核心也显示管理部门，AP 不再恒 3）。
  经营阶段底部不是「结算」而是「预算」tab（TurnScreen 轨道按钮，Turn.tsx:207）：
    预算页（PreviewPage）= 只读汇总 + 区间 → 点「确认本月方案并结算」直接 settleMonth →
    报表 → 进入下月。
```

## 4. 界面数字总览

### 4.1 顶部 HUD（`src/ui/Hud.tsx`）

| 显示 | 来源 |
|---|---|
| N 月 / Qn | `state.month`（12 个月圆点指示器） |
| 气候名 | `state.climate`（6 气候之一，季度切换时改变） |
| 动能 | `state.momentum`（扩张/停滞/收缩，`MOMENTUM_NAMES` 显示；季度切换时按当前气候 `MOMENTUM_ODDS` 掷出，决定本季度气候移动方向，见 §5.1） |
| 现金 | `state.cash`（角 → w）。**结算前是「月初现金」**：完整模式采购/打牌/招聘已实时扣；核心模式采购计划未付款，所以核心模式的 HUD 现金 = 结算前口径 |
| AP `x/max` | `state.ap / d.apMax`：max = 3 + max(0, 管理人数−1) + 事件修正（derive.ts:379）。AP 消耗：招聘 1、供应商开发 1、签协议 1、事件选项 0~2 |
| 提案 `x/max` | `state.plays / d.playsMax`：打牌次数，max = 管理≥4人?3:2 + 事件修正（derive.ts:380）。每月打牌数与 AP 独立 |
| 目标胶囊 | 基本目标达标状态 + 挑战目标完成百分比（`goalDisplay`，engine.ts:390） |

HUD **不显示**：借款额度/已借（`creditInfo` 是未使用的导出）、销售资源池、产能。这些只能从部门页看到。

### 4.2 经营页（按部门 tab 切换，底部轨道 + 红点提示）

轨道红点（Turn.tsx:177-183）：运营（手牌>0 且有打牌次数）、采购（有未选档且零库存的原料）、生产（低端可产 >0）、销售（有订单）、研发（有研发人员但无在研项目）。

每个部门页都有「本月账务」（LedgerSection，Turn.tsx:16-130）：`derive().deptLedger` 生成的复式记账行（工资计提/支付、折旧、加班费、研发投入、招聘费、提案费用、利息、采购入库、领料出库、成品入库、销售收入/成本等），点击金额可展开计算说明。

#### 运营部（完整模式专属）
- 提案卡列表：可打性 = `plays>0 且 现金≥实施费用 且 满足 minStaff`（actions.ts:246）。打出扣现金 + 1 次打牌数，效果并入 `cardMods` 当月生效（部分卡是即时效果，见 §12）。
- 「已实施」列表把效果区分为「持续性效果 / 即时效果」（启发式：effect 含 orders 或 flags 即算即时）。

#### 采购部
- **产品 BOM 看板**（Turn.tsx:394）：每个已解锁产品一行：配方（每件原料消耗）、成品库存件数、`avgCost`（账面均价展示值）。
- **原料采购表**（Turn.tsx:427）：每行原料的列 = 库存(+计划到货)/上限、供给（`d.materials[id].supply`）、价格水平（`tierShift` 五档名 极低/低/基准/高/极高）、库存成本（移动加权平均单价；核心模式选档后显示 `原均价 → 计划后均价`）、库存占用（`(库存+计划到货)/仓容`，仅核心模式）、操作（采购/调整）。
- 完整模式：选档立即执行 `buyMaterial`（扣现金、入库、记账「借 库存/贷 现金」）。
- 核心模式：选档只写 `chosenLot`（采购计划），显示「计划支出 / 结算前现金 / 已选采购档 x/y」汇总卡；结算时 `executePlannedPurchases` 统一执行（actions.ts:690）。
- **选档弹窗**：三档（小批/中批/大批）各显示「数量 × 单价 = 总价」；单价可展开「价格拆解」：基础价 + 气候修正 + 事件修正 + 卡牌修正 + 采购 4 人降价 + 批量修正（小 +1 档 / 大 −1 档）→ 最终单价。
- 其他采购手段：**贸易商**（随机 1~2 个品种的小批报价，价格 +1 档、不占档数、每品种每月限购 1 次，C4 卡增加配额；actions.ts:785）、**长期协议**（采购 ≥3 人解锁；1 AP + 1w 手续费；锁定 3 个月（采购 5 人 6 个月）中批到货 + 锁定签约时档位价；协议名额 1（5 人 2 个）+ J2 +1 + C5 强化 +2；actions.ts:828）。
- **供应商开发**（仅新材料 复合材/微机电）：1 AP + 3w，基础供给 +2，最多 3 次（上限 6）（actions.ts:889）。

#### 生产部
- **产能分配**：本月产能 `cap`、已安排、剩余三个数（`planCapacity` = d.capacity + 加班 10；actions.ts:964）。每个已解锁产品线一行：可产上限 `maxBy[t]`（受产能池剩余 + 该线 BOM 原料剩余双重约束，含其他线已排产占用，actions.ts:972-991）、排产数量（+ / − / 拉满）。
- **生产单位成本**（`productionUnitCosts`，actions.ts:667）：每线 = 材料成本（BOM 消耗 × 采购计划后原料均价 × 降本系数）+ 固定分摊（生产工资 + 折旧 + 加班费 ÷ 本月总排产量，排产为 0 则不分摊）。销售页的「单件毛利」与预算页的「预计毛利」都用这个数。
- **加班**（生产 ≥3 人解锁，按钮 Turn.tsx:1010）：勾选后本月产能 +10、结算时付 0.5w（actions.ts:1120）。
- **设备**（完整模式）：三种产线（见 §7.4）。
- 完整模式有「确认生产安排」按钮（立即扣料入库）；核心模式没有（结算统一执行）。

#### 销售部
- **本月需求与售价** 表（SellPage，Turn.tsx:1238 起）：每层一行 6 列 = 需求数（`d.demand`，含销售资源加点）、上限（`demandBase + pushCap`，超配显示「超 n」）、市价（`d.price`）、单件毛利（市价 − 生产单位成本，正金负红）、可用库存/可承诺量（`committable − 强制订单占用 − 已接订单占用`；核心模式 committable 含本月排产，actions.ts:1147）。
- **订单需求表**：本月全部订单（渠道自然订单 + 卡牌/事件强制订单）：数量、来源、订单价（`priceAtProduct(tier, o.priceShift + d.priceShift)`）、按订单价算的单件毛利、状态按钮（接单/已接·取消/已放弃·接回/强制必交；可接条件 = 该层可承诺量 ≥ 订单量，actions.ts:1163-1188）。
- **销售资源分配**：资源池 `d.salesResource`（基础 10 + 销售人员阶梯 + 知产 + 品牌加成 + 事件），按层分配（+1 步 = 该层 1 点需求的成本：低 1 / 中 2 / 高 4 / 特 6），每层需求加点上限 = 3×基础需求（15/12/6/3）（§8.2）。

#### 研发部
- 人员池 `x/5`、已放置人数、本月研发费用 = 在研项目数 × 3w（`d.rndActiveCount × d.rndCost`）。
- 两个主题弹框（新产品 BOM / 知识产权技能树）：草稿态调人数，「确认放置」批量写回并锁定本月（`flags['rndConfirmed']`，下月初可再调）；「关闭」= 还原草稿。
- 项目行：进度条（当前 `progress/need` + 金色标记 = 结算后位置）、基础成功率 / 放置 N 人后的动态成功率、5 格人员槽位（未招到的人员虚化）。
- 完整模式另有「知识产权」激活槽卡（§10.4）。

## 5. 市场环境：气候 / 需求 / 价格

### 5.1 气候与季度切换

- 6 气候环形序列：复苏 → 繁荣 → 过热 → 滞涨 → 衰退 → 萧条 → 复苏（`CLIMATE_ORDER`，data/game.ts:84）。
- **季度切换时**（进入新季度首月的 advanceMonth，settle.ts:873-888）：
  - ① 按当前气候的概率表 `MOMENTUM_ODDS`（data/game.ts:112，§3.1.1）掷经济动能：扩张/停滞/收缩，各气候概率不同（复苏/繁荣 70% 扩张；过热 70% 收缩；滞涨 70% 停滞；衰退/萧条 70% 收缩——经济惯性）。
  - ② 动能定方向：扩张=前进、收缩=后退、停滞=原地；步长独立掷：70% ×1 / 20% ×0 / 10% ×2；`move = 方向 × 步长`。
  - ③ 写入 `nextClimateOdds`（下一季度的转移预测）= 动能概率 × 步长分布，**与真实转移分布一致**（各气候不同；如自过热：−1 = 49%、−2 = 7%、原地 = 32%、+1 = 10.5%、+2 = 1.5%）。
  - 动能在 HUD 气候名旁显示（Hud.tsx）；测试见 `momentum.test.ts`（含各气候 3000 次频率统计）。
- 开局气候 = seed 决定的 6 等分随机（game.ts:35）。

### 5.2 气候对原料的影响（`CLIMATE_MATERIAL`，data/game.ts:71）

### 5.3 产品需求（`derive.ts:303-325`）

基础需求（`BASE_DEMAND`）：低端 5 / 中端 4 / 高端 2 / 特殊 1。

气候需求修正（`CLIMATE_DEMAND`）：复苏 −1、繁荣 +3、过热 +4、滞涨 −2、衰退 −3、萧条 −4。
**修正值按 60/40 拆分到低端/中端**：`lowShare = ceil(|v|×0.6)×sign`，`midShare = floor(|v|×0.4)×sign`；高端/特殊**不受气候需求修正**。

```
自然需求 base[层] = max(0, BASE_DEMAND[层] + 气候份额 + 事件需求修正[层])
销售加点 push[层] = min( floor(该层分配资源 / 该层成本), 3×BASE_DEMAND[层] )
总需求 demand[层] = base + push        ← 界面上的「需求数」
```

例：繁荣月低端自然需求 = 5 + 3×0.6 向上取整 = 5 + 2 = 7；若分配 3 点低端资源（成本 1）→ 总需求 10。

## 6. 采购机制

### 6.1 采购档数与选档规则

- 可选采购档数 `buyLots` = `BUY_LOT_SLOTS[min(5, 采购人数)] + 事件修正`，档位表 `[2,3,4,5,6,7]`（data/game.ts:282；derive.ts:364）。即 0 人 2 档、1 人 3 档、2 人 4 档、3 人 5 档、4 人 6 档、5 人 7 档。
- 每类原料每月**最多选一档**（`chosenLot`）；完整模式选中即扣现金入库；核心模式选中只形成计划。
- 采购 2 人：贸易商品种 +1（traderOffer 返回 2 个品种，actions.ts:787）。
- 采购 3 人：解锁长期协议（§6.4）。
- 采购 4 人：所有原料价格降 1 档（derive.ts:296）。
- 采购 5 人：协议 2 名额 + 锁定期 6 个月（STAFF 解锁文案）。

### 6.2 档位数量与价格（`lotQty` / `lotPrice`，actions.ts:458/475）

对当月供给 `S`：

```
批量原料（取整后档位严格递增）：小批 = ceil5(0.25S)，中批 = ceil5(0.5S)，大批 = S
稀缺原料（供给太小）：小批 = max(1, round(0.25S))，中批 = min(S, max(小批+1, round(0.5S)))，大批 = S
```

例（繁荣月，供给 = 基础 + 气候 +2/+2/+1/0）：包材 S=27 → 小 10 / 中 15 / 大 27；树脂 S=16 → 小 5 / 中 10 / 大 16；合金 S=8 → 小 2 / 中 4 / 大 8；芯片 S=3 → 小 1 / 中 2 / 大 3。

价格 = 档位表[2 + 当前 tierShift + 批量修正 + 卡牌修正]，其中**小批 +1 档、中批 0、大批 −1 档**；卡牌修正 = 本月已打采购卡的 `buyTierShift` 累加（C1 批量采购 −1/−2、C3 压价 −2/−3、C8 供应商关系 −1/−2）＋ C8 的「上月也打」额外 −1（该条件实际失效，见 §18）。
入库量还受仓容截断：`plannedLotQty = min(lotQty, 仓容 − 现有库存)`。

### 6.3 核心模式采购计划（`setPurchasePlan`，actions.ts:555）

- 选档不扣现金，但做两个预检：**计划总额 ≤ 当前现金**（多项计划共享同一笔现金）；**档数上限**。
- 生产可用原料 = 现有库存 + 计划到货（`materialAvailableForProduction`，actions.ts:623）。
- 若减少/取消采购后「库存 + 新计划量 < 该原料 BOM 需求」→ **生产计划整体清空**（含加班标志），已接订单同步重整（`reconcileAcceptedOrders`），日志提示重排产；取消（置 0）时若会清空生产则**拒绝**（必须先动生产）。
- 结算时 `executePlannedPurchases` 按「库存 + 计划」移动加权平均入库并扣现金，随后清空 `chosenLot` 与 `lotsUsed`（避免与实体库存叠加，actions.ts:690）。

### 6.4 长期协议（`signAgreement`，actions.ts:847）

- 条件：采购 ≥3 人、名额未满、1 AP + 1w 手续费（手续费当期费用化，进财务费用）。
- 内容：锁定**签约时的价格档位**（新材料额外 +1 档）× `monthsLeft`（3 或 6）个月，每月自动到货中批量。
- 结算执行（settle.ts:84-131）：按仓库剩余容量与**当前现金**检查；仓满或现金不足 → 整月跳过（警告），但锁定期照扣。到货按锁定档位价付款入库，记账「借 库存/贷 现金」。
- 可无条件终止（`cancelAgreement`）。
- 事件/卡牌来源的协议**免费**（不占 AP/现金），且默认原料 = 包材（`MATERIALS[0]`，见 §18）。

### 6.5 库存会计

- 入库（`addMaterial`，actions.ts:752）：现金 −= 入库量 × 单价；`value += 同额`；移动加权平均。
- 唯一现金扣减与库存入账同函数，防「入库没付钱」漏洞。
- 库存成本列 = `value / qty`（采购表显示取整值；核心模式选档后显示计划执行后的新均价 `plannedMaterialUnitCost`，actions.ts:632）。

## 7. 生产机制

### 7.1 产能（`derive.ts:338` + `makerCapacityPerStaff`，data/game.ts:292 / derive.ts:550）

```
每人产能 = 5 + (生产≥2人 ? 1 : 0) + (生产≥4人 ? 1 : 0) + 设备数 × 2
本月产能 = max(0, 5[老板自产] + 生产人数 × 每人产能 + 事件/卡牌产能修正)
排产可用产能 = 本月产能 + (加班 且 生产≥3人 ? 10 : 0)      （planCapacity，actions.ts:964 / settle.ts:566）
```

产能阶梯（0 设备）：0 人 5、1 人 10、2 人 17、3 人 23、4 人 33、5 人 40；加班（3 人起）分别 +10。设备每台为每名工人 +2（`makerCapacityPerStaff`，data/game.ts:292；derive 层 `makerPerStaff`，derive.ts:550）。
1 点产能 = 1 件产品，所有已解锁产品线共享同一产能池（多产品矩阵排产）。

### 7.2 BOM 与领料（`BOMS`，data/game.ts:157）

| 产品 | 配方（每件） | 基准售价 |
|---|---|---|
| 低端 标准品 | 包材 ×2 + 树脂 ×1 | 6w |
| 中端 精工件 | 树脂 ×2 + 合金 ×1 | 12w |
| 高端 精密件 | 合金 ×1 + 芯片 ×1 | 24w |
| 特殊 特种件 | 微机电 ×1 + 复合材 ×1 + 合金 ×1 | 36w |

- 节材修正：I1 工艺优化（−1）/ J12 精益生产（−2），单件最低消耗 1（`d.matSave`）。
- 排产上限 `maxProducible(tier)`（actions.ts:972）= min(该线剩余产能, 各 BOM 原料可用量 ÷ 单件消耗向下取整)；原料可用量扣除**其他线排产已预留**的部分（共享原料竞争）。
- 领料出库（`issueMaterials`，actions.ts:1005）：按账面单价等比例减记原料 `value`，记账「借 制造费用 / 贷 库存 X」。
- 成品入库：`p.value += 本批成本 × costFactor`；单位成本入账后 `avgCost = round(value/qty)`。
- **降本系数**（卡牌 P2/P7 `costFactor` 0.9/0.8）：成品按系数折价入账，差额 = 本批原料成本 × (1 − costFactor) 记为「生产降本差异」进当期生产费用（settle.ts:184-205，保证资产负债表恒等式）。
- **流水线成就**（生产 5 人）：每 5 件额外入库 1 件，按本批单位成本入账并贷记「营业外收入」（`postProductionInbound`，actions.ts:1042；settle.ts:197-205）。

### 7.3 两条执行路径

- **完整模式**：「确认生产安排」→ `confirmProduction`（actions.ts:1086）立即按 BOM 扣料、成品入库（受当时原料/产能上限截断），各线计划清零，结算时不再重复。
- **核心模式**：`confirmProduction` 返回「核心模式生产在结算时统一执行」；结算 §2 段统一执行（settle.ts:160-225），路径与确认共用 `issueMaterials/postProductionInbound`。
- 两条路径结算上限不同：确认路径按「当时」maxProducible（含其他线预留），结算路径用 settle 内部版本（仅产能 + 库存，不扣其他线预留——因为结算时其他线同时结算）。

### 7.4 设备（完整模式；`EQUIPMENT_SHOP`，data/game.ts:300）

| 设备 | 价格 | 月折旧 | 标注产能 | 标注借款额度 |
|---|---|---|---|---|
| 标准产线 | 5w | 0.2w | 10（旧模型，未使用） | 5w（未使用，见 §18） |
| 精密产线 | 9w | 0.35w | 16（未使用） | 8w（未使用） |
| 自动化产线 | 15w | 0.5w | 24（未使用） | 12w（未使用） |

新产能模型下设备只通过「每台 +2 每人产能」生效（`makerPerStaff`）；购置资本化为固定资产（不进当期损益），折旧逐月进生产费用（提足原值即停）；事件 P6/D9/X9 也会白送或低价送设备（按对价入账，免费则按公允价值 5w 确认营业外收入，actions.ts:1453-1470）。
「安置 1 人」的描述文案是旧槽位模型遗留，新模型无槽位概念。

### 7.5 加班（`toggleOvertime`，actions.ts:1120）

生产 ≥3 人解锁；勾选 = 本月产能 +10（进入 planCapacity 与预演），结算时付 0.5w（现金流出在结算 §2 段；费用同时进生产费用）。完整/核心模式都有（核心模式 UI 也显示加班卡，Turn.tsx:1010）。

## 8. 销售机制

### 8.1 订单（`Order`，types.ts:135）

- **自然订单（渠道订单）**：每月立项阶段生成 `orderCount` 单（`generateMonthlyOrders`，engine.ts:272）：
  ```
  orderCount = SALES_ORDER_COUNT[min(5,销售人数)] + I9(+1)/J8(+2)/J11(+1) + 事件 orders 修正
             销售 0-1 人 0 单；2-3 人 1 单；4-5 人 2 单
  每单数量 = max(1, orderQty + rng.int(5) − 2)     orderQty = 事件/卡指定，缺省 10 → 数量 8~12
  层次 = 已解锁层次里随机；订单价偏移 = 1 + J8/J11(+1) + 事件 orderPriceShift
  ```
  招聘销售跨过 2 人/4 人阈值当月**立即补发**差额订单（actions.ts:84-108）。
- **强制订单**：事件 P9 / 卡牌 S3 / S8 生成，`forced = true`（到月必交，不可取消）；`grantOrder`（actions.ts:415）的层次优先选**有库存的最低层**，无库存则选最高已解锁层。
- **接取规则**：
  - 完整模式：可承诺量 = 现有成品库存；核心模式：可承诺量 = 库存 + 本月排产（`committableProductQty`，actions.ts:1147）。
  - 可接条件 = 可承诺量 − 强制订单占用 − 其他已接订单占用 ≥ 订单量（`availableForOrder`，actions.ts:1152）。
  - 接单后占用该层可承诺量；排产减少时 `reconcileAcceptedOrders` 自动取消无法足额履约的已接订单（恢复为未接状态，不是「已放弃」，加回排产可再接）。
  - 不接 / 取消的自然订单**当月失效**（结算时全部订单清场，不跨月；`dueMonth` 字段仅展示）。
- **结算交付**（settle.ts:254-277）：未解锁层次的订单整单失效（警告）；未接自然订单失效；交付量 = min(订单量, 库存)，不足部分失效、**无违约惩罚**；订单价 = 产品档位表[2 + 订单价偏移 + 当月市场价偏移]；交付件占用本层需求池（订单先于现货结算）。

### 8.2 现货与需求加点（`derive.ts:309-325`，settle.ts:279-300）

```
销售资源池 = 10 + 销售人员阶梯(4/8/14/20/28，data/game.ts:272，derive.ts:559 累加) + I4(+3)/J3(+8) + 品牌加成(销售5人 +3 / J3 +3) + 事件修正
每层加点 = min( floor(分配量 / 成本[层]), 3×基础需求[层] )
           成本：低 1 / 中 2 / 高 4 / 特 6（SALES_PUSH_COST）；上限：15 / 12 / 6 / 3
总需求[层] = 自然需求 base[层] + 加点
```

- 现货成交（结算 §3 段，settle.ts:281-300）：每层 `可售 = min(库存, 本层剩余需求)`，按 `d.price`（含当月档位偏移）成交，现金入账，存货按账面均价结转成本。各层**独立**结算，跨层不互吃需求。
- **两模式现货均确定**（原核心模式随机因子已移除）：实际市场需求 = 总需求 × `factor`，`factor` 恒 1（settle.ts:236-241）。`spotDemandFactor` 保留为测试注入入口（如 0.5 用于桥接检查）。预演直接取结算结果，min≡max。
- **需求满足率** = 已成交（订单占用 + 现货）÷ **自然需求 base 合计**（玩家自己推大的加点盘子不拉低自己的达标率；settle.ts:252）。

### 8.3 销售页数字

- 单件毛利（市价 / 订单价口径）= 对应单价 − `productionUnitCosts.tiers[t].total`（§7 统一成本口径，含固定分摊，与损益表毛利口径不同，见 §18）。
- 「可用库存 / 可承诺量」= committable − 订单占用。

## 9. 人员系统（五部门）

### 9.1 招聘（`hire`，actions.ts:66）

### 9.3 工资（权责发生制，settle.ts:405-425）

### 10.1 放置模型（`setRndAssign` / `confirmRndAssignments`，actions.ts:1265/1293）

- 前提：研发 ≥1 人。把人员「放置」到项目：每人每月 +5 进度、+5% 成功率（`rndProjectOutcome`，derive.ts:600；封顶 90%，中端教学项 100%）。

## 13. 董事会目标

### 13.1 规则（完整模式专属）

- 季度首月（1/4/7/10）：从当季池抽 1 个**基本目标**（必达，10 分）+ 2 个**挑战候选**（二选一，可放弃；15~25 分）。

- 季度末结算时判定（settle.ts:490-525）；达成基本目标重置 `misses`。
- 挑战目标值若引用「基本目标 × N」，在基本目标确定后换算（`makeTrack`，engine.ts:186）。

### 13.2 目标池（data/game.ts:588-730；Q1 用 OPENING 池）

- **Q1 基本（3 选 1）**：B1 季度净利润 ≥ 0；B2 季度收入 ≥ 30w；B3 季度完成 1 次招聘（**指标恒 0，见 §18**）。

- **后续季度**：每气候 3 基本 + 6 挑战（如复苏 RB1-3/RC1-6：净利润 ≥ 上季 ×1.1 + 2w、季末现金 ≥ 上季末 + 5w、1 次设备购买或研发立项；挑战含基本 ×1.5、现金 ≥ 20w 无逾期、2 次研发立项、2 个月毛利 ≥ 6w、员工 ≥ 8、收入 ≥ 上季 ×1.3；其余气候同构，含负债率、存货压缩、需求满足率、高端收入占比 30% 等）。

- HUD 目标胶囊：基本达标图标 + 挑战完成百分比。
- GoalsSheet：两目标当前值/目标值/差距/进度条、历史季度记录、董事会耐心（misses 0~2）。

## 14. 财务系统

### 14.1 现金流动全景（谁扣现金、何时扣）

| 支出 | 扣现金时点 | 进损益科目 |
|---|---|---|
| 普通采购（完整模式） | 选档立即 | 资产内部转换（库存），售出才进成本 |
| 采购计划（核心模式） | 结算 §0 段 | 同上 |
| 协议到货 | 结算 §0 段（现金不足整月跳过） | 同上 |
| 招聘费 / 裁员返还 | 发生即扣（净额） | 管理费用（招聘费） |
| 打牌实施费用 | 打出即扣 | 管理费用（卡费单列） |
| 事件现金代价 | 选事件即扣 | 财务费用（杂项）；设备类 = 资本支出 |
| 协议手续费 1w / 供应商开发 3w | 发生即扣 | 财务费用（杂项） |
| 加班费 0.5w | 结算 §2 段 | 生产费用 |
| 研发投入 3w×在研数 | 结算 §4 段 | 研发费用 |
| 借款利息 | 结算 §4 段 | 财务费用 |
| 上月工资 | 结算 §4 段（实付） | 无（费用上月已计提确认） |
| 所得税 10% | 结算 §4 段 | 所得税 |
| 销售回款 | 结算 §3 段（订单 + 现货） | 销售收入 |

**工资计提**：当月 `wagePayableBy` = 各部门（人数 × 月薪）；下月实付。资产负债表的「应付职工薪酬」即挂账额；终局净资产也扣减它（`computeScore` 的 assetsEnd）。

### 14.2 损益表科目构成（`settle` §4 段，settle.ts:345-440）

```
毛利 = 销售收入（订单 + 现货） − 销售成本（按账面均价实际结转额）
生产费用 = 生产工资 + 设备折旧 + 加班费 + 生产降本差异（(1−costFactor)×本批原料成本）
销售费用 = 销售工资
管理费用 = 运营工资 + 采购工资 + 招聘费净额 + 全部卡费
研发费用 = 研发工资 + 3w×在研项目数
财务费用 = 借款利息 + (事件/杂项支出 − 卡费)
营业外收入 = miscIncome（流水线 bonus 计价、事件赠与、设备公允价值等）
税前利润 = 毛利 − 五费用 + 营业外收入
所得税 = max(0, round(税前 × 10%))
净利润 = 税前 − 税 → 累计进 retained（留存收益）
```

- 折旧：每台 `min(月折旧, 原值 − 累计折旧)`，提足即停（账面不穿负）。
- 利息：`max(0, round(debt × rate) − I5)`，`rate = max(0, 0.8% + 事件利率修正×0.1% − J7×0.1%)`。**当前 UI 无借款入口 → debt 恒 0、利息恒 0**（§18）。

### 14.3 资产负债表（`balanceSheet`，game.ts:252）

```
资产 = 现金 + 原料存货(value 合计) + 成品存货(value 合计) + 设备净值(原值−累计折旧, ≥0) + 待收挂账
负债 = 借款(debt) + 应付挂账(pendingCost) + 应付职工薪酬
权益 = 实收资本(10w) + 股东实物投入(0) + 留存收益
恒等式：资产 = 负债 + 权益（多 seed 全年审计偏差 = 0，audit.test.ts）
```

注意 UI 报表（Panel/Report）的「负债与权益合计」显示为 `debt + wagePayable + equity`（不含 pendingCost，展示口径简化）。

### 14.4 借款（引擎完整、UI 未暴露）

- `borrow`（actions.ts:1366）：1w 为单位，≤ 可用额度，`noBorrow`（X3 信贷冻结）禁止；现金 +、debt +。
- `repay`：≤ debt 且 ≤ 现金。
- 额度 = round((20w + J7 20w) × 事件额度系数)；**设备的标注额度与 R6 事件的「额度 +5w」都未接入**（§18）。
- 测试脚本（route/balance）里用借还稳现金流，所以引擎路径本身是活的，只是玩家界面没有按钮。

### 14.5 报表与下钻

- 报表页（Panel「报表」tab）：按月切换 → 利润表 / 资产负债表 / 财务比率（毛利率、净利率、需求满足率、资产负债率、债务权益比、权益乘数）/ 累计（收入、毛利、净利润、净资产、现金、借款）。利润表科目可下钻明细。
- 结算报表（ReportSheet）：本月经营摘要（产量/订单交付/现货/满足率）、警告列表、协议到货、研发逐项目结果、损益表、资产负债表、总览、科目下钻。
- 日志页：按类型（事件/董事会/结算/操作）过滤的时间线，可展开明细。

## 15. 结算顺序与经营预演

### 15.1 `settle()` 执行顺序（settle.ts:76）

```
§0 长期协议自动到货（仓容 + 现金检查，失败整月跳过并警告）
   核心模式：先执行采购计划（executePlannedPurchases，入库 + 扣现金 + 清档位）
§1 研发（在生产之前，保证解锁当月可排产）：
   逐项目 progress += 放置人数×5 + 平修正；progress ≥ need 时按成功率掷骰
   （Rng 种子 = rngState + 月×7919，确定性）；成功 → 完成、释放人员、授效；失败 → 进度保留
§2 生产：逐线按排产执行（产能 + 原料截断）→ 领料出库 → 流水线 bonus → 成品入库
   → 加班费 0.5w 现金流出
§3 销售：先订单（强制 + 已接自然；交付 = min(订单量, 库存)，不足失效；占用本层需求池）
   后现货（每层 min(库存, 剩余需求)；两模式均按公开需求 100%）
   销售收入 / 销售成本记账（借 现金·销售成本 / 贷 销售收入·存货）
§4 过账：现金 −(研发 + 利息) − 上月工资；计提本月工资；税前利润 → 10% 税；retained += 净利润
§5 季度末（月 %3==0）：判定基本/挑战目标 → 得分、misses；记录季度快照
§6 终局：现金 < 0 → 败（资金为负）；misses ≥ 2 → 败（连两季未达）；月 ≥ 12 → 胜
```

结算报告 `SettleReport`：生产（产能/计划/实际/领料明细/逐线）、销售（订单/现货/收入/需求/满足率/lost）、研发逐条、损益表、资产负债表、协议到货、警告。

### 15.2 预算预演（核心模式「预算」页，preview.ts:132）

- **预计收入 / 毛利 / 期末现金**：克隆状态运行一次真实 `settle()`；现货确定，min≡max（测试：core-loop.test.ts「正式结算结果落在预演区间内」）。
- 逐产品拆分：计划生产 / 订单交付（确定值）/ 现货预计成交（确定值）/ 订单收入（确定）/ 现货收入（确定）/ 单件毛利 = 市价 − 统一口径单位成本（preview.ts:148）/ 订单毛利（确定）/ 现货毛利（确定）。
- **预计期末现金两段桥**（`preSettleCash`，preview.ts:57）：
  结算前 = 月初现金 − 采购计划 − 协议模拟 − 加班 − 研发 − 利息 − 上月工资（确定性；为负 = 计划超资金能力，警告）；
  结算后 = 结算前 + 订单回款 + 现货回款 − 所得税（随回款浮动）。
- 研发进度段：结算层确定性判定（与区间无关），显示「成功下月生效 / 失败保留可重投 / 进度未满」。
- 明确不做：风险提示等级、瓶颈识别、自动建议、库存预测。

### 15.3 完整模式「结算」确认弹窗（App.tsx SettleFlow）

显示：本月排产、产能、销售资源使用、现金、AP、可实施数 + 风险提示（现金为负将破产 / 基本目标未达标 / 手牌超限 / 剩余 AP）。确认后 `settleMonth` → 报表 → 下月。

## 16. 胜负与评分

- **败**：任一月份结算后 `cash < 0`（资金为负）；或连续 2 个季度未达成基本目标（完整模式）。
- **胜**：走完 12 个月结算（`month >= 12`）。
- **总分**（`computeScore`，settle.ts:797；每次结算实时刷新 `state.score`）：
  ```
  盈利分 = round(12 个月累计净利润 ÷ 10w × 1.5)
  资产分 = round(期末净资产 ÷ 10w × 1.0)     净资产 = 现金 + 存货 + 设备净值 − 借款 − 应付工资
  目标分 = 各季度基本/挑战得分累计（10 / 15~25）
  成就分 = 5 个满员成就 × 10
  总分 = 以上四项之和
  ```
- 终局页（EndScreen）：胜/负标题 + 出局原因 + 四分明细（含口径说明）+ 累计净利润 + 期末净资产 + 成就标签。

## 17. 核心模式与六个固定场景

### 17.1 场景（`scenarios.ts`；标题页入口，可复现）

1. **B3 目标（季度完成 1 次招聘）恒不可达**：`hiresTotal` 只在抽目标时快照（engine.ts:147），后续招聘不更新该 flag → `hiresQ` 指标恒 0；一旦抽到 B3 且未达成会累计 misses。

### 建议的改动切入点（按「玩家能否在结算前回答四个问题」评估）

交接文档（`docs/core-loop-handoff.md` §6）给出的验收标准：玩家能否回答 ①为什么采购这些原料 ②为什么选这个产品组合 ③为什么接这些订单、资源投哪些市场 ④改一个决定后现金/库存/销量/毛利怎么变。改动任何系统前，对照 §18 先确认目标机制是否真的「活」着：

- 想让**融资**起作用 → 给 UI 加借/还入口并接入设备额度/R6 修正（§18-A1/7/8）。
- 想让**销售决策更深** → 现货目前是「库存 min 需求」自动成交，玩家唯一杠杆是需求加点与订单选择；可考虑让玩家选售价档位或现货折价（交接文档 §4.4 待确认项）。
- 想让**卡牌**有存在感 → C6/C7/C9/C10 四张空卡要么补执行界面要么移出牌池；P10 库存清理同理。
- 想让**订单张力**更强 → 当前无违约惩罚、不跨月（交接文档 §4.3 待确认项）；`dueMonth` 字段已存在但未参与结算。
- 想修**目标体系** → 先修 B3/hiresTotal 快照 bug（§18-B1）。
