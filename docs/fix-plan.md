# 分阶段修改计划

> 依据 `docs/design-review.md` 的审查结论。原则：**每个阶段独立可交付、可验证**；先修"循环断裂"（P0），再升级核心决策（P1），再补全机制与宏观节奏（P2/P3），最后统一重校数值（P4）与体验层（P5）。数值重校放在死效应清理之后，避免在"规则还没定死"的引擎上调数。

## 决策清单（开工前需拍板）

| # | 决策项 | 建议 |
|---|---|---|
| D1 | 开局现金：60w 直降 vs 保留 100w + 股东垫款（第 3 月起每月还本 5w） | 先做 60w（改动小、可回退），垫款作 P5 备选 |
| D2 | 事件奖励分定义 | 机会事件每参与 1 次 +2 分，上限 12 |
| D3 | 基础贸易商：改为"采购 2 人解锁 1 份报价"，C4 卡给 +1 份 | 采纳（与 4 人"品种 +1"层次干净） |
| D4 | 订单交付月：**延期作废**（已确认）——取方案 B"订单当月事"：四类订单全部当月结算、删除 `dueMonth` 字段、自然订单不延期（库存不足 → 部分交付、余量当月失效）。历史延期设计经讨论作废，其他机制已提供足够决策密度 | 采纳（2026-07 确认） |
| D5 | R6 逆向工程保证入堆（8 选 6 → 8 选 5，R6 必入） | 采纳（终局双通道：研发主线 + R6 副线） |
| D6 | 生产招聘费：一次性 2w/人（原为 0） | 采纳，doc §6.1.3 同步改 |

> 新增决策项请续编 D7 起；D4 曾论证"下月交付"（见审查文档 1.2 与 git 历史），2026-07 确认作废，取方案 B。

## 阶段 0：守循环的 bug 修复（约 1 天）

目标：不动规则语义，只修"引擎对了、咬合错了"的地方。

- **0.1 事件叠加守卫**（review 1.3）
  `beginMonthEvent`（engine.ts）加 `if (state.flags['evDrawn:' + state.month]) return`，抽完置位；`App.tsx` fallback 逻辑不变。
  验证：headless 模拟 App 流程（复用审查时的 appsim 脚本，转成 `eventflow.test.ts`）：每种子每月事件抽 1 张。
- **0.2 B3 招聘目标 bug**（review 2.2）
  `hire()`（actions.ts）每次递增 `state.flags['hiresTotal']`；`snapshotQuarter`（settle.ts）加 `hiresTotal` 快照；`drawBoardGoals` 保留季初对账（depts 累计）。
  验证：新增 goal 测试——Q1 抽到 B3 的种子，招 1 人后 `goalCurrent ≥ 1`。
- **0.3 C4 目标缺 param**（review 2.2）
  `OPENING_CHALLENGE C4` 补 `param: 40`。
- **0.4 R6 事件毒丸选项**（review 1.4）
  `MonthMods` 加 `creditBonus?: Money`（月度额度加成都），`mergeMods` 累加、`derive.creditLine` 读入；R6 选项 A 改为 `mods: { creditBonus: 50, rateShift: 1 }`（+5w 额度与 +1w 利率都在文案语义内），删掉 `extraCredit` 累积 flag 依赖。
  验证：选择 A 后 `derive.creditLine` 当月 +50、利率 +0.1%。
- **0.5 S4 裁员额度接 UI**（review 1.4）
  `OpsPage`（Turn.tsx）：`monthFlags` 含 `canFire` 时，对 staff>0 的部门显示"解雇 1 人（返还 50% 招聘费）"按钮，调 `fire()`。
  验证：事件测试——S4 当月解雇后 staff -1、现金 +refund、`hireFeeBy` 负向冲减。
- **0.6 P3 加班卡"支付 2w 升级"**（review 1.4，小改提前做）
  `playCard` 支持 `opts.upgrade`：基础 +3→+5（强化 +5→+8）产能，UI 打牌弹窗加"支付 2w 升级"勾选项。

验收：`vitest run` 全绿 + 事件叠加模拟 0 次重复抽取。

## 阶段 1：核心决策升级（约 2~3 天）

目标：把"单线拉满"变成"月度布局"。这是决策密度最大的一阶段，放 P0 之后单独做、单独回归。

- **1.1 生产计划矩阵化**（review 1.1）
  - `types.ts`：`plan: { plans: Record<Tier, number>; overtime: boolean }`；新增月度已用产能由 `sum(plans)` 推导，无需额外字段。
  - `actions.ts`：`setPlan(tier, qty)` 按层写入；`maxProducible(state, tier)` 计入 `已排产总数` 对产能的占用；`confirmProduction` 逐层扣料入库（每层独立 BOM/领料/流水线加成），产能约束在**全月合计**上执行。
  - `settle.ts` 生产段：遍历 `plans` 中未确认部分，逐层结算（与 1.2 的订单占用交互：订单占用的库存不影响生产）。
  - `Turn.tsx` MakePage：4 行真实分配矩阵（每行 stepper + "可产 X（原料缺 Y）"提示 + 总产能条），删掉"自由腾挪"失实文案；"剩余产能" = 总产能 − 已排产。
  回归：audit 恒等式零漂移；route/balance bot 改为按矩阵排产（低端 + 高端组合），记录基线分。
- **1.2 订单当月闭环（D4 确认：延期作废，取方案 B）**（review 1.2）
  规则一句话：**当月产生的订单，当月结算交付，不延期。**
  - 删除 `dueMonth` 字段（`types.ts` / `generateMonthlyOrders` / `grantOrder` / `hire()` 销售渠道订单）；展示层如需提示写"本月交付"。
  - 自然订单：接单 → 库存锁定；结算时库存不足按现有行为"部分交付、余量失效"（引擎现状即正确，只需删掉"延期"语义）；弃单 → 当月失效。
  - `SellPage`：hint"不足留到下月"改为"不足则部分交付、余量当月失效"；订单表去掉交付月概念。
  - doc §7.2.7 v1.2"订单两类"段落标注"延期规则已作废（D4）"，保留接单/弃单权衡文案。
  回归：订单流测试（生成→接单→结算交付→不足失效 全路径）；bot 行为与现状一致，无需改。

验收：`生产 3 高端 + 15 低端` 的组合在引擎层成立且产能合计不超上限；订单全部当月结算、无 `dueMonth` 残留。

## 阶段 2：宏观节奏（约 1.5 天）

目标：让每局的"经济波形"真的不同。

- **2.1 动能表接入**（review 1.5）
  `advanceMonth` 季度切换段：先按 `MOMENTUM_ODDS[state.climate]` 掷动能，再按动能掷步长（扩张/收缩 70%±1 / 20%停 / 10%±2；停滞 70%停 / 15%左 / 15%右，doc §3.1.1 原文表），写 `state.momentum` 与气候。
  单测：跑 2 万个季度切换，各气候占比与理论分布卡方一致（重点：过热后出现滞涨的概率 ≈ 0.7×0.7+0.7×0.1…按表算）。
- **2.2 气候预测 UI**（review 1.5）
  `nextClimateOdds` 改为按 2.1 真实分布计算；董事会页/事件页显示"下季预测：X% / Y% / Z%"。
- **2.3 季度事件池**（review 1.4 §3.2）
  `state` 加 `eventQueue: string[]` + `quarterPoolBuilt: boolean`：季度首月按 §3.2 权重建 15 张池（排除上季已抽 3 张），洗牌取 3 张为本季队列；每月 `shift()` 取 1 张；队列空则回退加权随机。
  单测：同一季度 3 事件不重复；下季池不含上季已用事件。

验收：60 种子 × 12 月的气候序列两两不同的比例显著提升（对比当前"只有起点偏移"）。

## 阶段 3：死效应清理（约 3~4 天，分三批交付）

总原则：**每条要么实现、要么删文案**（review 1.4）。每批配针对性引擎测试（打出卡 → 断言效果真实发生）。

- **3.1 采购批**（C4/C6/C7/C9/C10/C8 + 基础贸易商，决策 D3/D5 关联项）
  - C9 期货：打牌时写入 `pendingFutures[mat] = 锁价档位`（强化版全原料）；`advanceMonth` 时 `pendingFutures → futures`（清旧值）；下月 `lotPrice` 取 `min(市价档, 锁价档)`。
  - C6 紧急采购：新增 `buyUrgent(matId)` 动作：小批量 +2 档价、不占 `lotsUsed`、当月 ≤2 次（强化版中批 +1 档）；UI 采购页加按钮。
  - C7 原料替换：新增 `swapMaterial(src, dst, qty)`：按 dst 现价结算、src 按账面单价冲减（差额进现金与部门账务）；强化版额外 +2 单位目标原料。
  - C10 清仓：新增 `clearanceBuy(matId)`：小批 −2 档价；结算时若当月未采购其他原料（lotsUsed=0 且无贸易商/紧急）则 +2 单位（同价）。
  - C8 链条：月末若本月打出过 C8 → `flags['lastC8']=1`，未打出清零；下月 `buyCardShift` 已读它（现有逻辑生效）。
  - 基础贸易商：`traderOffer` 份数改为 `buy≥2 ? 1 : 0`（+buy4 品种 1→2 保持），C4 当月 +1 份且 buy≥3 可指定品种（强化 +2 份、免加价）。
- **3.2 生产批**（P1 满负荷 / P3 已由 0.6 覆盖）
  - P1：结算时若"全月排产 = 产能上限"（1.1 矩阵口径），产量 +1（强化 +2）。
- **3.3 研发/事件批**（临时知产 / J5 / 事件奖励分）
  - 临时知产季化：`monthMods.tempIps` → 状态级 `quarterTempIps: string[]`（季度切换清空），`activeIps` 读它；O10/R4 文案"持续到本季结束"成立。
  - J5 专利壁垒：激活 J5 时每季第 1 次"复制上月打出的一张卡入手牌"（action + 季度 flag），文案与现有"每季度可复制一张已打出的卡"一致。
  - 事件奖励分（决策 D2）：`acceptChance` 记 `flags['eventChanceCount']`，`computeScore.event = min(12, count×2)`；终局页加"事件分"行，§1.4 文案落地。
  - 基础销售资源 10 → 6 留到 P4 与数值一起 A/B（影响早月加点价值）。

验收：审查清单中 1.4 表格全部勾选"实现"或"文案已删"；每张改动过的卡有对应引擎断言。

## 阶段 4：数值重校（约 2 天 + bot 回归）

目标：在"规则已定死"的引擎上统一调参（决策 D1/D5/D6）。

- **4.1 开局**：`START_CASH` 1000 → 600（D1）。
- **4.2 BOM/供给**：中端 BOM 改 `{resin:1, alloy:1}`（stdCost 60，对齐 doc §7.2.3）；特殊 BOM `stdCost` 150 → 170（展示修正）；芯片 `baseSupply` 3 → 4（库存上限 8 → 10）；`bom-special` 成功率 0.4 → 0.5；R6 必入堆（8 选 5，D5）。
- **4.3 轨道成本**：生产人员招聘费 0 → 一次性 2w（D6，doc §6.1.3 同步改）。
- **4.4 评分**：盈利系数 1.5 → 1.2，资产系数 1.0 → 1.5（终局页说明同步）；事件分按 3.3 接入。
- **4.5 设备折旧**：标准 20 → 5（10 个月提足）、精密 35 → 8、自动 50 → 12；事件 D9"折旧减半" = 2.5w/月（25 角），P6/X9 事件设备按对价 5w/8w 入账后折旧同步取 5/8。
- **4.6 开局目标池重校**（对"零招聘基线"）：B2 30w → 90w；C1 10w → 30w；C5 50w → 100w；C4 保留 4w（param 已在 0.3 修）。
- **4.7 bot 回归与验收门**：
  - 扩展 `route.test.ts`：组合流 bot（高端 3~4 + 低端余量）、特殊冲分 bot（研发 3 人 + R6 + 供应商开发 ×2 + 芯片/合金囤货）。
  - 300 种子跑：① 保守流生存 ≥ 25/30 且**组合流/特殊流中位分 > 保守流 ≥ 10 分**（投资有回报，P4 调参成功标志）；② 破产原因中"资金为负"占比 ≥ "目标未达"的 50%（现金流张力复活）；③ 得分中位数落在 150~200 区间。
  - 不达标项回到 4.1~4.6 微调（每次只动 1 个参数）。

验收：三份 bot 基线报告存档于 PR 描述（种子数/生存率/中位分/最低分），供后续改动回归。

## 阶段 5：体验层（约 2 天）

- **5.1 存档 + seed**：`GameState` 全量 JSON（含 `rngState`）每月结算后写 localStorage；标题页"继续/输入 seed"；round-trip 测试（序列化→反序列化→跑 3 月→与不存档路径逐字段相等）。
- **5.2 HUD 预估总分**：实时 = 累计净利×1.2 + (现金+存货+设备净值−负债)×1.5 + 目标分 + 成就分 + 事件分；对应 `design-system.md §4.5` 预留的 stat 盒。
- **5.3 事件面板档位行**：即时事件显示"本月价格档位：包材 基准→低 / 利率 0.8%→0.9%"（从 `derive` 取 delta）。
- **5.4 气候预测展示**（若 2.2 未随阶段 2 上线则补上）。
- **5.5 早月加点价值**：基础销售资源 10 → 6（与 4.7 一起 A/B，若保守流中位分掉 > 8 分则回退保留 10）。

验收：断网刷新一局 12 月不丢档；预估分与终局实际分误差 < 10%（同策略自跑对比）。

## 依赖与风险

| 阶段 | 依赖 | 主要风险 | 对策 |
|---|---|---|---|
| 0 | 无 | 小 | 每子项独立测试 |
| 1 | 0 | 状态形状变化（plan 重构）波及全部 bot/测试 | 无存档期直接改，一次性迁移 bot；audit 恒等式做闸门 |
| 2 | 0 | 气候分布变化引起平衡漂移 | 只改分布不改当月数值；P4 统一回归 |
| 3 | 1（P1 满负荷判定依赖矩阵口径） | 采购批动作多，UI 改动大 | 分三批交付，每批独立可回退 |
| 4 | 3 | 参数间耦合（芯片 4 影响高端/特殊双线） | 每次只动 1 参数 + 300 种子回归门 |
| 5 | 4（预估分系数依赖 4.4） | 存档体积/性能 | 状态 < 100KB，可忽略 |

**建议交付节奏**：阶段 0 当天合入；阶段 1 一次 PR（引擎 + UI 分开两个 commit 便于 review）；阶段 2/3 可并行（动能表不动卡牌，采购批不动气候）；阶段 4 必须串行在 3 之后；阶段 5 随时可插入但不与 4 同 PR。
