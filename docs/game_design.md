# 1 游戏定位

一款单机、Roguelike、以12个月为周期的生产经营刷分游戏。玩家扮演总经理，分配资金、招募员工、构筑卡组，让“资金→资源→产品→资金”的循环越转越大。

- 核心张力
    - 短期现金流 vs 长期资产投入
    - 专精部门 vs 均衡发展
    - 确定性订单 vs 高风险现货

## 1.2 核心体验

- 每局不同：事件、卡池、强化分支随机，逼迫调整策略
- 引擎构筑：从弱到强，后期爆发
- 分数优化：同一套规则反复挑战最高分
- 报表模拟：玩家的行动，会严格专业地反应到财务报表中，深化玩家对报表科目的直观理解

## 1.3 关于报表模拟

- 报表是自动生成的，结算后自动过账，月底展示
- 每个科目可点开，看得到月底的数字具体是怎么计算而来的
- 原料库存按 **移动加权平均** 计价
- 采购人员薪酬计入 **管理费用**
- 长期协议锁定价格与实际采购价差异，按实际支付入账
- 贸易商溢价计入原料采购成本
- 财务比率只在月底报表展示，董事会目标用绝对数，不用比率
- 财务比率可以作为得分的一个维度：
    - 连续 3 个月毛利 ≥ 8w
    - 负债 ≤ 净资产 × 0.3

## 1.4 游戏目标

- 12个月后，总分最高。
- 总分 =
    - 盈利分 = 12个月累计净利润/10 × 系数
    - 资产分 = 结束时净资产/10 × 系数
    - 目标分 = 董事会目标奖 + 成就奖 + 事件奖励分

# 2 核心循环

## 2.1 核心资源

- AP
- 现金
- 原料（包材、树脂、合金、芯片，及研发解锁的新材料）
- 产品/库存
- 产能
- 销售资源
- 研发进度
- 知识产权槽
- 借款额度

资金 ——> 原料 ——> 产品 ——> 销售 ——> 资金

## 2.2 游戏阶段

一个回合代表一个月度。

- **事件阶段**：抽事件卡，确定本月背景参数
- **董事会阶段【每三个月一次】**：宣布季度基本目标，选择季度挑战目标
- **抽卡阶段**：按部门人员结构加权抽卡，选卡入手，抽N选M
- **经营布局阶段**：分配资源
    - 招募各部门员工、构建固定资产、研发方向
    - 采购原料、选择生产产品（不同BOM）、针对不同产品安排销售力量
    - 打出卡牌，利用各种效果创造有利条件或化解不利条件
- **结算阶段**：根据经营布局阶段的安排，进行各类结算
    - 主业务结算：资金-原料-产品-收入的循环
    - 其他业务结算：研发进展、借款周期
    - 报表结算：游戏自动完成账务处理，形成本月度报表
- **进入下个月**的事件阶段

## 2.3 结束条件

- 立即失败：
    - 结算后资金为负
    - 连续两季度未完成董事会目标
- 12个月正常结束：计算总分
- 失败局不计分

# 3 事件阶段

事件阶段的作用包括：
- 改变本月整体经营环境：需求、价格、供给、销售资源、资金成本等
- 制造每局差异：不同气候、不同事件组合

## 3.1 事件标签

### 3.1.1 气候

- 【气候】模型：经济周期六阶段
- 每季有1种主气候，共6种
    - 复苏：需求低但回升，原料价格低、利率/资金低
    - 繁荣：需求高，原料价格稳定，利率资金中
    - 过热：需求极高，原材料价格大涨，资金/利率高
    - 滞涨：需求下滑，原材料价格高，资金/利率高
    - 衰退：需求低，原材料价格下跌，资金/利率下降
    - 萧条：需求极低，原材料价格极低，资金/利率低但信贷紧

- 【经济动能】
    - 扩张：70%向右移动1格，20%停留、10%向右移动2格
    - 收缩：70%向左移动1格，20%停留，10%向左移动2格
    - 停滞：70%停留，15%向左移动1格，15%向右移动1格

- 气候的确定
    - 首季度，6种随机
    - 后续季度，根据上季气候+经济动能（随机）提供的概率，生成下季气候

每季度开始时的第一个月，在弹出事件前，宣布本季气候，并预测下季度气候概率。

### 3.1.2 类型

- 即时事件：抽到后立即结算，修改本月参数，月底清除；直接改变本月经营环境
- 抉择事件：抽到后必须二选一，每个选项都有代价或收益，让玩家用资源换安全，或用风险换收益
- 机会事件：可参与也可以放弃，放弃通常无事发生，参与有成本，收益通常正面

### 3.1.3 极性

正面、负面、中性

### 3.1.4 作用域

- 资金
- 采购
- 生产
- 销售
- 研发
- 管理

## 3.2 事件池

- 每种气候拥有10张专属事件卡
- 事件池15张
    - 非端点气候：当季气候8张 + 相邻气候各2张，其他气候各1张，每月从中抽1张
    - 端点气候：当季抽9张，其他气候各1张
- 每季开始时构建一次事件池，本季3个月从池中抽3张，抽后不可再使用，下一季的事件池由排除已用事件的卡牌组成。

# 4 董事会阶段

- 给玩家季度方向
- 提供分数来源
- 与报表绑定：目标多与财务指标有关，强化报表模拟体验

## 4.1 UI要点

- 生成并宣布本季度基本目标：基本目标达成加10分，未达成0分
    - 连续两次未达成基本目标的，游戏结束
- 展示2个挑战目标，玩家2选一。不可放弃。
- 目标进入【经理室】面板最上部

## 4.2 目标基础机制

- 基本目标：每季度初，根据当季气候，从该气候的 3 个基本目标中随机抽 1 个，直接下达，不能选，但可申诉一次。
- 挑战目标：从该气候的 6 个挑战目标中随机抽 2 个，玩家二选一，或放弃。
- 数值公式：上季度实际值 × 增长率 + 固定值

## 4.3 目标池

### 4.3.1 气候：复苏

**基本目标（3选1）**
1. 本季度累计净利润 ≥ 上季度 × 1.1 + 2w
2. 季度末现金 ≥ 上季度末现金 + 5w
3. 本季度完成1次设备购买或研发立项

**挑战目标（6选2）**
1. 本季度累计净利润 ≥ 基本目标 × 1.5
2. 季度末现金 ≥ 20w 且无逾期借款
3. 本季度完成2次研发立项
4. 本季度至少2个月毛利 ≥ 6w
5. 季度末员工总数 ≥ 8
6. 本季度销售收入 ≥ 上季度 × 1.3

### 4.3.2 气候：繁荣

**基本目标（3选1）**
1. 本季度累计收入 ≥ 上季度 × 1.2 + 5w
2. 本季度累计净利润 ≥ 上季度 × 1.15 + 2w
3. 季度末净资产 ≥ 上季度末 × 1.1 + 5w

**挑战目标（6选2）**
1. 本季度累计收入 ≥ 基本目标 × 1.4
2. 本季度至少2个月总需求满足率 ≥ 90%
3. 季度末设备总数 ≥ 3
4. 本季度高端产品收入 ≥ 总收入的30%
5. 本季度连续3个月毛利 ≥ 8w
6. 季度末员工总数 ≥ 10

### 4.3.3 气候：过热

**基本目标（3选1）**
1. 本季度单位原料采购成本 ≤ 上季度 × 1.1
2. 本季度至少2个月毛利 ≥ 5w
3. 季度末现金 ≥ 15w

**挑战目标（6选2）**
1. 本季度连续3个月毛利 ≥ 6w
2. 本季度累计净利润 ≥ 上季度 × 1.2
3. 季度末负债 ≤ 总资产 × 0.4
4. 本季度至少1个月总需求满足率 ≥ 95%
5. 签订并生效1份长期供货协议（需采购3人解锁）
6. 季度末存货 ≤ 上季度末存货 × 0.8

### 4.3.4 气候：滞涨

**基本目标（3选1）**
1. 季度末现金 ≥ 上季度末现金 × 0.8
2. 季度末负债 ≤ 上季度末负债
3. 本季度累计净利润 ≥ 0

**挑战目标（6选2）**
1. 本季度累计净利润 ≥ 上季度 × 1.1
2. 季度末负债 ≤ 净资产 × 0.3
3. 本季度至少2个月毛利 ≥ 4w
4. 本季度薪酬支出 ≤ 上季度 × 0.9
5. 本季度研发成功1项
6. 季度末存货 ≤ 上季度末 × 0.7

### 4.3.5 气候：衰退

**基本目标（3选1）**
1. 季度末现金 ≥ 10w
2. 本季度薪酬支出 ≤ 上季度 × 0.9
3. 本季度完成1次低价设备购买或研发立项

**挑战目标（6选2）**
1. 本季度累计净利润 ≥ 上季度 × 1.2
2. 季度末负债 ≤ 净资产 × 0.25
3. 本季度研发成功率 ≥ 50%，或完成1项研发
4. 本季度至少2个月毛利 ≥ 5w
5. 季度末设备总数 ≥ 3
6. 本季度销售收入 ≥ 上季度 × 1.1

### 4.3.6 气候：萧条

**基本目标（3选1）**
1. 季度末现金 ≥ 15w
2. 本季度不新增借款，或借款总额 ≤ 上季度末
3. 本季度完成1次设备抄底或知识产权收购

**挑战目标（6选2）**
1. 季度末现金 ≥ 30w
2. 本季度累计净利润 ≥ 0
3. 季度末负债 ≤ 净资产 × 0.2
4. 本季度完成2次低价资产购买
5. 本季度研发成功1项，且成本 ≤ 3w
6. 下季度开始前，现金 ≥ 上季度末 × 1.5

## 4.4 第一次董事会目标池

第一次董事会发生在第 1 季度第 1 个月，此时没有“上季度”数据，因此所有目标使用**绝对数值**，不引用上期。

首季度气候随机，但目标池统一使用“开局目标池”，不按气候区分。  
原因是：首季度气候已经通过事件和需求影响经营环境，目标再按气候分化，会让开局运气成分过重。

### 4.4.1 开局基本目标（3选1）

每局第一次董事会，从以下 3 个中随机抽 1 个，直接下达：

| 编号 | 基本目标 | 说明 |
|---|---|---|
| B1 | 第 1 季度累计净利润 ≥ 0 | 不亏损即可 |
| B2 | 第 1 季度累计收入 ≥ 30w | 跑通销售循环 |
| B3 | 第 1 季度完成 1 次招聘（至少 1 人） | 开始搭建团队 |

达成加 10 分，未达成 0 分。  
连续两次未达成基本目标，游戏结束。

### 4.4.2 开局挑战目标（6选2）

每局第一次董事会，从以下 6 个中随机抽 2 个，玩家二选一，不可放弃：

| 编号 | 挑战目标 | 说明 |
|---|---|---|
| C1 | 第 1 季度累计净利润 ≥ 10w | 盈利要求 |
| C2 | 季度末现金 ≥ 35w | 现金储备 |
| C3 | 季度末员工总数 ≥ 3 | 团队规模 |
| C4 | 第 1 季度至少 2 个月毛利 ≥ 4w | 持续盈利 |
| C5 | 第 1 季度累计收入 ≥ 50w | 销售规模 |
| C6 | 第 1 季度完成 1 次研发立项 | 研发启动 |

挑战目标达成后，按董事会规则加分。  
具体加分值在董事会阶段统一处理，通常为 10~20 分。

### 4.4.3 后续季度

从第 2 季度开始，恢复使用原有目标池，即按当季气候，从该气候的 3 个基本目标和 6 个挑战目标中抽取，数值公式为“上季度实际值 × 增长率 + 固定值”。

## 4.5 目标追踪 UI

### 4.5.1 位置

目标追踪面板固定在 **【经理室】面板最上部**，始终可见。  
无论玩家在抽卡、采购、生产、销售界面，都能看到当前季度目标进度。

### 4.5.2 每个目标卡片显示内容

每个目标显示为一张卡片，包含：

| 元素 | 说明 |
|---|---|
| 目标名称 | 如“本季度累计净利润” |
| 目标类型 | 基本 / 挑战 |
| 目标描述 | 完整规则文字 |
| 当前值 | 系统实时计算 |
| 目标值 | 固定值或公式计算后的值 |
| 进度条 | 当前值 / 目标值 |
| 状态图标 | 进行中 / 已达标 / 未达标 |
| 剩余差距 | 还差多少 |

### 4.5.3 自动计算逻辑

系统每时每刻根据最新报表数据更新目标进度，玩家不需要手动计算比例。

#### 累计型目标

例如：本季度累计净利润 ≥ 10w

- 当前值 = 本季度已过月份的净利润之和
- 目标值 = 10w
- 进度条 = 当前值 / 目标值
- 达标判断：当前值 ≥ 目标值

#### 时点型目标

例如：季度末现金 ≥ 35w

- 当前值 = 最新现金余额
- 目标值 = 35w
- 进度条 = 当前值 / 目标值
- 达标判断：当前值 ≥ 目标值

#### 条件型目标

例如：本季度完成 1 次研发立项

- 当前值 = 已完成次数
- 目标值 = 1
- 进度条 = 当前值 / 目标值
- 达标判断：当前值 ≥ 目标值

#### 比率型目标

例如：季度末负债 ≤ 净资产 × 0.3

- 系统自动计算：
  - 当前负债 = X
  - 当前净资产 = Y
  - 允许上限 = Y × 0.3
- 显示为：
  - 负债 10w / 上限 15w
  - 进度条 = 负债 / 上限
  - 达标判断：负债 ≤ 上限

玩家看到的是“负债 10w，上限 15w，达标”，不需要自己算 0.3。

### 4.5.4 状态图标

| 状态 | 图标 | 说明 |
|---|---|---|
| 进行中 | ⏳ | 尚未达标，但季度未结束 |
| 已达标 | ✅ | 当前值已满足目标 |
| 未达标 | ❌ | 季度已结束且未达标 |
| 已失效 | — | 挑战目标未选择，不追踪 |

### 4.5.5 显示示例

假设第 1 季度基本目标为“累计净利润 ≥ 0”，挑战目标选择了“累计净利润 ≥ 10w”。

第 1 个月结束：

| 目标 | 当前值 | 目标值 | 进度 | 状态 |
|---|---:|---:|---:|---|
| 基本：累计净利润 ≥ 0 | 2w | 0 | 达标 | ✅ |
| 挑战：累计净利润 ≥ 10w | 2w | 10w | 20% | ⏳ |

第 2 个月结束：

| 目标 | 当前值 | 目标值 | 进度 | 状态 |
|---|---:|---:|---:|---|
| 基本：累计净利润 ≥ 0 | 5w | 0 | 达标 | ✅ |
| 挑战：累计净利润 ≥ 10w | 5w | 10w | 50% | ⏳ |

第 3 个月结束：

| 目标 | 当前值 | 目标值 | 进度 | 状态 |
|---|---:|---:|---:|---|
| 基本：累计净利润 ≥ 0 | 8w | 0 | 达标 | ✅ |
| 挑战：累计净利润 ≥ 10w | 8w | 10w | 80% | ❌ |

### 4.5.6 挑战目标二选一后的处理

挑战目标抽取 2 个，玩家选择 1 个后：

- 选中的目标进入追踪面板；
- 未选中的目标不追踪，不显示在面板中；
- 如果玩家想查看未选中的目标，可在“董事会记录”中查看，但不参与结算。

### 4.5.7 季度结束时的结算

季度最后一个月结算完成后：

- 系统自动判断每个目标是否达标；
- 基本目标达标：+10 分；
- 挑战目标达标：按挑战目标分值加分；
- 未达标：0 分；
- 连续两次基本目标未达标：游戏结束。

结算后，目标面板清空，进入下一季度董事会，生成新目标。

# 5 抽卡阶段

## 5.1 卡牌系统

- 开局确定卡池：基础卡池 + 部门人数加权。
- 赠送开局起始手牌：3选2
- 每月固定顺序：
    - 抽 N 张：从池中随机抽 N 张。
    - 选 M 张：从 N 张中选 M 张加入手牌。
    - 未选中的放回牌库
    - 检查手牌上限，弃到上限
    - 进入经营布局阶段，打出卡牌，打出卡牌不消耗AP。

## 5.2 UI

在抽卡的时候，应该可以查看当前手牌，每局可打的牌，AP余额，以进行选牌、弃牌的决策。

选牌界面显示每张牌的类型、效果、是否已强化。

弃牌界面显示弃牌堆内容。

手牌可随时查看，打牌时高亮可打出的牌。

## 5.3 抽卡权重公式

### 总牌库

每业务部门 10 张专属卡牌：2 张核心卡 + 8 张普通卡。
管理卡最多 4 张，通过管理人数解锁加入牌库。

### 5.3.1 卡池构建

每局开始时构建本局牌库：

- 业务部门核心卡必然进入本局牌库，普通卡从 8 张里随机选 6 张。未被选中的2张本局不可用。
- 业务卡牌库 = （4+6）× 4 = 40张。
- 管理卡通过管理人数解锁，加入牌库。
- 洗牌组成最终牌库。

核心卡：

| 部门 | 核心牌（×2） |
|---|---|
| 采购 | C1 批量采购、C5 长期协议 |
| 生产 | P1 满负荷、P2 质量管控 |
| 销售 | S1 促销活动、S3 大订单 |
| 研发 | R1 加速研发、R3 技术合作 |

### 权重

业务部门卡分四类：采购卡、生产卡、销售卡、研发卡

业务部门卡牌出现概率 = (该部门人数 + 1) / (四个业务部门招聘人数 + 4)

管理卡不参与加权，通过管理人数解锁加入牌库。

管理卡效果是抽牌、换牌、+AP、强化其他牌、弃牌换资源，从弃牌堆捞牌。

## 5.4 打牌规则

- 部分牌额外支付现金或其他资源。
- 每月可打牌数：初始2，管理4人3。
- 打牌时机：经营阶段均可，效果立即生效。
- 打出的牌进入弃牌堆，本局不再洗回，除非卡牌效果说明。

# 6 经营阶段

## 6.1 轨道系统：业务部门及人员效果

部门类似于【盖亚计划】里的轨道，玩家需要花费代价去：建立部门（开启），招聘人员（推进轨道），然后享受每个人员带来的固定效果，及推进轨道带来的解锁效果。

招聘人员行动会消耗1AP。
采购、生产、销售、研发四个部门的人数，会影响管理部门抽卡的种类分布、概率。

**每个部门统一提供两类效果：**

- **基础值**：每名人员带来的固定加成
- **解锁能力**：达到人数门槛后解锁的特殊能力

### 6.1.1 管理部门

#### 管理部门设定

- 招聘管理人员
- 展示当月可选卡牌，N选M
- 展示及打出手牌

#### 管理人员设定

- 招聘成本
    - 阶梯费用：5、4、3、2、1
    - 固定薪酬：1w

- **基础值**：每招募一人，增加1点AP上限，下月可用

- **解锁能力**：
    - 2人：增加当月可选卡牌上限：3->4
    - 3人：增加手牌上限：5->6
    - 4人：增加可打牌数为3，强化卡牌效果
    - 5人：增加可选上限 4->5，手牌上限 6->7，获得【金牌高管】成就，终局+10

### 6.1.2 采购部门

#### 采购部门设定

- 招聘采购人员
- 展示原材料：现货，市场价格，采购档位
- 采购原材料：按档位采购
- 签署长期供货协议
- 贸易商随机供货：现货，高于市场价格，每月种类随机

#### 采购人员设定

- 招聘成本
    - 阶梯费用：5、4、3、2、1
    - 固定薪酬：1w

- **基础值（固有效果，每多 1 人立即生效）**：
    - 每类原材料供给 +2
    - 每月可选档数 +1（0 人 2 档 → 5 人 7 档，见下表）
- **解锁能力**：
    - 2人：贸易商每月随机供应品种 +1
    - 3人：解锁长期供货协议能力，允许锁定未来 3 个月的供应（一次只能锁定一种，每月中批供应，价格锁定）
    - 4人：所有原料价格降 1 档，强化卡牌效果
    - 5人：允许同时签 2 份长期供货协议，且锁定期可选 6 个月，获得【供应链联盟】成就，终局 +10 分

#### 采购档位

每月根据市场供给上限，每类原料自动生成三档：

| 档位 | 采购量 | 价格 |
|---|---:|---|
| 小批 | 供给上限的 25%，向上取整到 5 | 基准价升 1 档 |
| 中批 | 供给上限的 50%，向上取整到 5 | 基准价 |
| 大批 | 供给上限 | 基准价降 1 档 |

> 稀缺原料（供给小到取整后档位量不再递增，约 ≤10 件）改用 1 件粒度：小批 ≈ 1/4 供给，中批 ≈ 1/2 供给，保证 小批 < 中批 ≤ 大批。

每类原料每月最多选一档。
每月可选总档数受采购人数限制：

| 采购人数 | 每月可选档数 |
|---:|---:|
| 0 | 2 |
| 1 | 3 |
| 2 | 4 |
| 3 | 5 |
| 4 | 6 |
| 5 | 7 |

### 6.1.3 生产部门

#### 生产部门设定

- 招聘生产人员
- 购买生产设备
- 已有 BOM 展示
- 实施生产，选择 BOM，执行批量生产

开局默认有一台设备，设备提供产能 10，一台设备能安置 1 名生产人员。

- 设备
    - 每月产生折旧
    - 每台设备能带来 5w 的 3 个月银行借款额度

#### 人员设定

- 招聘成本
    - 阶梯费用：无
    - 固定薪酬：0.5w

- **基础值**：每招募一人，有设备坑位的，产能 +4，无设备的，产能 +2
- **解锁能力**：
    - 2人：每个工人产能 +2
    - 3人：解锁加班，可支付加班费 0.5w/次，临时增加 10 产能，每月只能加班 1 次
    - 4人：每名工人产能 +1，强化卡牌效果
    - 5人：每生产 5 件，额外入库 1 件；获得【流水线】成就，终局 +10 分

#### 生产结算

- 本月产能 = 设备产能 + 生产人员加成 + 卡牌/事件修正
- 本月产量 = 本月产能
- 原料消耗 = 产量 × BOM
- 产品入库 = 产量

不再有良率、废品、投料产出比。

### 6.1.4 销售部门

#### 销售部门设定

- 招聘销售人员
- 销售资源分配：特定产品销售资源分配越多，产品吸引力得分越高
- 实施销售结算：存货 -> 现金（第一版不引入应收账款）
- 订单展示

初始销售资源：10

#### 销售人员设定

- 招聘成本
    - 阶梯费用：5、4、3、2、1
    - 固定薪酬：1.5w

- **基础值**：每招募一人，立即增加销售资源

| 销售人数 | 每人销售资源 | 总销售资源 |
|---|---:|---:|
| 0 | 0 | 10 |
| 1 | +4 | 14 |
| 2 | +4 | 18 |
| 3 | +6 | 28 |
| 4 | +6 | 34 |
| 5 | +8 | 46 |

- **解锁能力**：
    - 2人：渠道建设，每月可以带来 1 个确定性订单
    - 3人：每个销售带来的销售资源上升（每人 +4 变 +6）
    - 4人：渠道升级，每月可以带来 3 个确定性订单
    - 5人：每个销售带来的销售资源大幅上升（每人 +6 变 +8），且实现成本转移，即当月原料涨价的，可以同时 100% 提升产品价格，使毛利不受原料涨价影响。获得【品牌】成就，终局 +10 分

### 6.1.5 研发部门

#### 研发部门设定

- 展示产品开发界面：研发出新的 BOM
- 展示技术开发界面：研发出可持续生效的知识产权
- 每月只能推进一个研发项目
- 研发进度累积，进度满后判定成功率

#### 研发人员设定

- 招聘成本：阶梯 5、4、3、2、1w
- 固定薪酬：2w/月
- **基础值**：每名研发人员，研发进度 +2/月，研发成功率 +5%
- **解锁能力**：
    - 2人：无
    - 3人：可同时激活 2 个知识产权
    - 4人：无
    - 5人：可同时激活 3 个知识产权，获得【专利壁垒】成就，终局 +10

#### 研发项目

**产品开发**

| 项目 | 进度需求 | 基础成功率 | 解锁 |
|---|---:|---:|---|
| 中端 BOM | 30 | 70% | 中端产品配方 |
| 高端 BOM | 50 | 55% | 高端产品配方 |
| 特殊 BOM | 70 | 40% | 特殊产品配方 |

低端 BOM 开局自带。

**技术开发**

| 项目 | 进度需求 | 基础成功率 | 解锁 |
|---|---:|---:|---|
| 普通知识产权 | 30 | 70% | 从普通池随机抽 1 个 |
| 强力知识产权 | 50 | 50% | 从强力池随机抽 1 个 |

#### 研发进度

> 本月进度 = 研发人数 × 2 + 卡牌修正 + 事件修正

进度累积到项目需求后，月底判定成功率。

- 成功：解锁项目，进度清零
- 失败：进度保留，下月继续判定

#### 研发成功率

> 最终成功率 = 基础成功率 + 研发人数 × 5% + 卡牌/事件修正

上限 95%，下限 5%。

#### 知识产权

初始只能激活 1 个。
研发 3 人：可激活 2 个。
研发 5 人：可激活 3 个。
未激活的知识产权放在仓库，可随时替换，每月最多换 1 次。

# 7 核心系统：经济模型

## 7.1 原材料供应

### 基本原料数值

| 原料 | 层级 | 基础月供给 | 基准价 | 基础库存上限 | 主要服务 |
|---|---:|---:|---:|---:|---|
| 包材 | T1 | 24 | 1w | 40 | 低端产品 |
| 树脂 | T2 | 14 | 2w | 30 | 中低端产品 |
| 合金 | T3 | 7 | 4w | 15 | 中高端产品 |
| 芯片 | T4 | 3 | 8w | 8 | 高端产品 |

开局如果做低端产品，包材和树脂够用；做中端，合金开始卡；做高端，芯片严重不够。玩家必须通过招采购、签协议、走贸易商、研发替代材料来解锁更高端生产。

### 核心公式

- 每月每类原料的市场供给：
    - `市场供给 = 基础供给 + 气候修正 + 事件修正 + 采购人员加成`
- 采购按档位进行，不自由输入数量。

### 价格档位

所有价格用五档表示：

| 档位 | 包材 | 树脂 | 合金 | 芯片 |
|---|---:|---:|---:|---:|
| 极低 | 0.5w | 1w | 2w | 4w |
| 低 | 0.8w | 1.5w | 3w | 6w |
| 基准 | 1w | 2w | 4w | 8w |
| 高 | 1.5w | 3w | 6w | 12w |
| 极高 | 2w | 4w | 8w | 16w |

气候和事件只改变档位，不改变百分比。

### 气候影响

| 气候 | 包材供给 | 树脂供给 | 合金供给 | 芯片供给 | 价格档位 |
|---|---:|---:|---:|---:|---|
| 复苏 | +2 | +1 | 0 | -1 | 所有降 1 档 |
| 繁荣 | +3 | +2 | +1 | 0 | 不变 |
| 过热 | -2 | -3 | -3 | -2 | 所有升 1 档，芯片再升 1 档 |
| 滞涨 | -1 | -2 | -2 | -1 | 所有升 1 档 |
| 衰退 | +4 | +3 | +1 | 0 | 所有降 1 档 |
| 萧条 | +6 | +4 | +2 | 0 | 所有降 2 档，芯片只降 1 档 |

### 长期协议

采购 3 人解锁，一次只能锁一种原料。
每份协议：

- 每月固定供应**中批**该原料；
- 不占本月采购档数；
- 价格锁定 3 个月；
- 采购 5 人时，可同时签 2 份，且锁定期可选 6 个月；
- 签订消耗 1AP + 1w 手续费；
- 每月购买时仍需付钱，占库存。

### 贸易商

贸易商每月随机提供一种原料的**小批**，价格 +1 档。
采购 4 人后价格不变，但品种 +1。
贸易商不占本月采购档数，但占资金和库存。

## 7.2 销售与需求

### 7.2.1 销售模型总览

销售模型采用：

> **库存驱动为主，订单驱动为辅。**
> 先生产，再推销；订单提供确定性，现货提供高收益机会。

每月销售结算时，系统按以下顺序处理：

1. 生成本月总需求；
2. 将总需求分配到低端、中端、高端、特殊四个层次；
3. 先结算确定性订单；
4. 再结算各层次现货需求；
5. 未满足需求流失；
6. 未售出产品进入库存。

核心公式：

> **实际销量 = min（该产品库存，该产品获得的吸引力份额对应的需求）**

### 7.2.2 每月总需求生成

#### 基础总需求

| 层次 | 基础需求 |
|---|---:|
| 低端 | 5 |
| 中端 | 4 |
| 高端 | 2 |
| 特殊 | 1 |
| 合计 | 12 |

#### 气候需求修正

气候只改**总需求**，不改分层比例。

| 气候 | 总需求修正 |
|---|---:|
| 复苏 | -1 |
| 繁荣 | +3 |
| 过热 | +4 |
| 滞涨 | -2 |
| 衰退 | -3 |
| 萧条 | -4 |

气候总需求修正**只加在低端和中端**，高端和特殊不受气候影响。

建议分摊：

- 低端：+ 气候修正的 60%（向上取整）
- 中端：+ 气候修正的 40%（向下取整）

#### 事件需求修正

事件直接改某一层需求。

| 事件 | 低端 | 中端 | 高端 | 特殊 |
|---|---:|---:|---:|---:|
| 消费回暖 | +1 | +1 | 0 | 0 |
| 消费旺盛 | +1 | +1 | +1 | 0 |
| 需求爆棚 | 0 | +1 | +2 | +1 |
| 需求萎缩 | -1 | -1 | -1 | 0 |
| 订单取消 | -2 | -1 | -1 | 0 |
| 需求冰点 | -2 | -2 | -1 | -1 |

#### 最终需求

> **本月某层需求 = 基础需求 + 气候修正分摊 + 事件修正**

### 7.2.3 产品层次与基准价

产品分四个层次：

| 产品层次 | 典型 BOM | 原料成本 | 基准售价 | 基础毛利 |
|---|---|---:|---:|---:|
| 低端 | 2 包材 + 1 树脂 | 4w | 6w | 2w |
| 中端 | 1 树脂 + 1 合金 | 6w | 12w | 6w |
| 高端 | 1 合金 + 1 芯片 | 12w | 24w | 12w |
| 特殊 | 新材料 | 研发决定 | 36w | 研发决定 |

售价用五档表示：

| 档位 | 低端 | 中端 | 高端 | 特殊 |
|---|---:|---:|---:|---:|
| 极低 | 4w | 8w | 16w | 24w |
| 低 | 5w | 10w | 20w | 30w |
| 基准 | 6w | 12w | 24w | 36w |
| 高 | 7w | 14w | 28w | 42w |
| 极高 | 8w | 16w | 32w | 48w |

玩家不能自由定价，售价由事件和卡牌调整档位。

### 7.2.4 销售资源

销售资源是每月可分配的推销能力。

#### 初始销售资源

| 项目 | 数值 |
|---|---:|
| 开局销售资源 | 10 |

#### 销售人员效果

每招募 1 名销售人员：

- 立即增加销售资源；
- 固定薪酬 1.5w/月；
- 招聘成本阶梯：5、4、3、2、1w。

| 销售人数 | 每人销售资源 | 总销售资源 |
|---|---:|---:|
| 0 | 0 | 10 |
| 1 | +4 | 14 |
| 2 | +4 | 18 |
| 3 | +6 | 28 |
| 4 | +6 | 34 |
| 5 | +8 | 46 |

3 人解锁“每个销售带来的销售资源上升”：每人 +4 变 +6。
5 人解锁“大幅上升”：每人 +6 变 +8。

#### 销售资源分配

每月经营阶段，玩家将销售资源分配到各产品。

规则：

- 销售资源只能分配给本月有库存或已生产的产品；
- 每个产品至少分配 1 点才能参与现货销售；
- 未分配销售资源的产品，只能通过确定性订单销售；
- 销售资源不累积，每月重置。

### 7.2.5 吸引力公式

吸引力只用于**同层排序**，不决定总需求。

> **吸引力 = 分配销售资源 + 层次加成 + 品牌加成**

#### 产品层次系数

| 产品层次 | 层次加成 |
|---|---:|
| 低端 | 0 |
| 中端 | +2 |
| 高端 | +4 |
| 特殊 | +6 |

#### 品牌加成

| 条件 | 品牌加成 |
|---|---:|
| 无 | 0 |
| 销售 5 人解锁【品牌】 | +3 |

### 7.2.6 订单系统

订单是确定性销售渠道，不依赖吸引力。

#### 订单来源

| 销售人数 | 每月订单数 |
|---|---:|
| 0~1 | 0 |
| 2 | 1 |
| 3 | 1 |
| 4 | 3 |
| 5 | 3 |

#### 订单属性

每个订单包含：

- 产品层次要求；
- 数量；
- 价格档位；
- 交付月份。

订单价格通常为：

> **订单价格 = 基准价升 1 档**

订单不消耗销售资源，但需要生产对应产品。
订单可以放弃，放弃无惩罚。

#### 订单结算

订单在现货需求之前结算。
订单指定产品层次，玩家必须用同层次产品交付。
若库存不足，按实际库存交付，剩余订单量失效，无惩罚。

### 7.2.7 销售结算流程

每月结算阶段按以下步骤：

#### 第一步：结算订单

- 按订单列表逐一交付；
- 扣除对应产品库存；
- 计入销售收入；
- 订单不占用销售资源。

#### 第二步：计算各产品吸引力

- 对每个分配了销售资源且有库存的产品，计算吸引力；
- 吸引力 = 分配销售资源 + 层次加成 + 品牌加成。

#### 第三步：按层次结算现货需求

需求从高到低结算：特殊 → 高端 → 中端 → 低端。

每层需求只能由同层或更高层产品满足：

- 特殊需求：只能由特殊产品满足；
- 高端需求：由高端或特殊产品满足；
- 中端需求：由中端、高端或特殊产品满足；
- 低端需求：由低端、中端、高端或特殊产品满足。

同级需求，按吸引力从高到低排序产品，依次满足。

若某产品被用于满足更低层需求，售价按该层需求的价格上限计算，通常不划算，但可清库存。

#### 第四步：未满足需求流失

某层需求若没有足够产品满足，剩余需求直接流失，不转入其他层。

#### 第五步：未售出产品入库

未售出产品进入库存，下月可继续销售。
库存商品下月售价若受事件影响，按事件规则调整。

### 7.2.8 与报表衔接

销售结算后，自动生成以下科目：

| 科目 | 计算方式 |
|---|---|
| 销售收入 | 订单收入 + 现货销售收入 |
| 销售成本 | 已售产品 × 移动加权平均成本 |
| 销售费用 | 销售人员薪酬 + 销售卡费用 |
| 管理费用 | 管理人员薪酬 + 采购人员薪酬 + 其他 |
| 研发费用 | 研发人员薪酬 + 研发卡费用 + 事件费用 |
| 制造费用 | 生产人员薪酬 + 设备折旧 + 生产卡费用 |
| 毛利 | 销售收入 - 销售成本 |
| 净利润 | 收入 - 成本 - 费用 - 利息 - 税 |

每个科目可点开，查看明细。
财务比率只在月底报表展示，董事会目标用绝对数。

- 进度累积到需求后，月底判定
- 最终成功率 = 基础成功率 + 研发人数 × 5% + 卡牌/事件修正
- 上限 95%，下限 5%
- 失败保留进度，下月继续

### 7.4.3 知识产权

初始激活 1 个；研发 3 人激活 2 个；研发 5 人激活 3 个。
未激活的放在仓库，每月最多换 1 次。

普通池和强力池见 6.1.5。

### 7.4.4 新材料供应

- 研发成功新 BOM 后，新材料加入“已知材料”
- 初始市场供给 0
- 供应商开发：1AP + 3w，基础供给 +2，可重复 3 次，最高 6
- 采购人员“每类原料供给 +2”对已开发新材料生效
- 新材料可签长期协议，锁定价高 1 档，供应中批

### 7.4.5 研发与报表

- 研发全部费用化，不资本化
- 研发费用 = 研发人员薪酬 + 研发卡费用 + 事件费用
- 不确认无形资产

### 7.4.6 研发目标

- 研发立项：选择项目并投入至少 1 名研发人员
- 研发成功：进度满并判定成功

董事会目标中涉及研发的，均使用上述定义。
